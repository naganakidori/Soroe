## 性能の数字の扱い

手で測っては文書へ書き写す、を繰り返した結果、**数字が古いまま残り、しかもそれが
判断の根拠として誤りになる**ことが実際に起きた（「1 枚のエンコードは長くても数百 ms」が、
実際には PNG で 2.3 秒だった）。以下を守ること。

- **性能に関わる変更をしたら `--bench` を走らせる。** 通常の検証には含めていない（1 分近くかかるため）
- **文書やコメントに書く数字は、判断の根拠になるものだけにする。** 「速い」「十分」で足りるところに数字を置かない
- **残す数字には必ず「測定日・条件・再現コマンド」を添える。** 条件とは構成（Debug / Release）・
  標本（寸法と種類）・測り方（回数と中央値か）・何を含むか（エンコードのみか、読み込みから書き込みまでか）
- **絶対値は測定した機械に依存する。文書の数字と自分の環境の数字が一致しなくても、それ自体は
  異常ではない。** 記録してある値は 2026-08-10 に Intel Core Ultra 5 245K / Windows 11 / Release で
  測ったもの。別の環境では**比率で判断すること** — PNG の圧縮率 1・4・6 の関係（4 は 1 の 1.5 倍、
  6 は 4 の 3 倍）、形式ごとの桁の違い（JPEG と BMP が同程度、PNG がその 10 倍、WebP がさらに倍）
  といった関係は環境が変わっても保たれる。`--bench` は測定環境（CPU・OS・構成）を出力の先頭に
  出すので、比べるときはそこを確認する
- **`--bench` は既定では合成画像を使う**（リポジトリ外のファイルに依存させないため）。ただし
  **合成の写真は PNG 圧縮率の差を小さく見せる**ので、圧縮率の判断をやり直すときは実写を渡すこと

## 作業で踏んだ落とし穴

### `.ps1` の実行ポリシー

Windows クライアントの実行ポリシーは既定が `Restricted` で、`.ps1` **ファイル**の実行を
一切許さない（同じ内容を対話的に打ち込む分には通るので気づきにくい）。`-ExecutionPolicy Bypass`
を付け忘れると `UnauthorizedAccess` で止まる。

**エージェントのシェルは `Process` スコープが `Bypass` で起動されていることがあり、その場合
ここで止まらない。手元で通ったことが、利用者の環境で通る証拠にならない。** 利用者向けの
手順を書くときは必ず `-ExecutionPolicy Bypass` を付けた形で書く。恒久的に変えるなら
`Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` を各自で実行する。

### 相対パスはリポジトリ直下に解決される

`dotnet run` に `--nologo`（これは `dotnet build` の指定で、`run` では素通りしてアプリの
引数になる）を渡したせいで、リポジトリ直下に `--nologo` というフォルダができ、危うく
コミットするところだった。作業用ファイルを `%TEMP%` に置き、使い捨てのプログラムでも
出力先を絶対パスで受け取るのはこのため。ハーネスも作業フォルダは `Path.GetTempPath()`
配下にしている。

### 一括置換でソース 7 ファイルの全文字を壊した

- **PowerShell の `@(@('a','b'))` は平坦化される。** 外側の配列に要素が 1 つしかないと、
  `foreach` が受け取るのは内側の配列ではなく**その中の文字列**になる。結果
  `$pair[0]` / `$pair[1]` が先頭 2 文字を指し、`String.Replace(string, string)` ではなく
  **`String.Replace(char, char)` が呼ばれて全文字が置換される**（`OpenCvSharp` が
  `OpenLvSharp` になった）。組にして回すなら `,` で要素数を明示するか、
  ハッシュテーブルや `[PSCustomObject]` を使う
- **置換の確認を検索結果だけで済ませないこと。** このとき「`CLAUDE.md` という文字列が
  残っていないか」を検索して 0 件を得たが、**成功したからではなく、検索したい文字列
  自体が `LLGUDE.md` に化けていたから**だった。**通ったことが動いている証拠にならない**
  という、原則 2 のテストで繰り返し扱ってきたのと同じ形である
